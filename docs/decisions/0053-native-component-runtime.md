# ADR 0053: Native Atlas and terminal component dispatch

Status: accepted, November 15, 2026. Completes the native adapter portion of charter step 5; follows ADRs 0051 and 0052.

## Decision

Runtime component discovery selects compiled Atlas, Beacon and Missions libraries. It does not inspect a source checkout, resolve Bun or execute a component bridge. Atlas runtime operations use explicit private store roots, finite command admission, serialized blocking jobs and the existing runtime policy and intent ledgers. Configured executable Atlas hooks are refused for runtime operations.

Terminal component commands use native frontends with explicit cwd, environment, stdin and independent stdout, stderr and exit status. `luuna atlas`, `luuna beacon` and `luuna missions` dispatch before loading private runtime settings. Historical executable names emitted by component hooks and completions are recognized when this executable is installed under those names. Windows alias matching follows its case-insensitive executable names, and private IPC admission recognizes Windows environment-name case variants before any raw library dispatch. Packaging those names remains release work.

Managed Atlas calls opt into thread-local YAML expansion/text budgets that restore the previous policy on completion or unwind. Raw library comparisons retain their Go behavior. The private raw IPC mode is refused by managed terminal admission because it accepts independent file paths. Managed terminal hooks, recipes and Git commands use finite child capture. Unix calls clean up owned process groups. Windows children are created suspended, assigned to a private kill-on-close Job Object, and only then resumed; completion and errors explicitly terminate that job and wait for its active-process count to reach zero before joining pipe readers. Failed ownership kills and reaps the suspended child. Other hosts refuse managed child execution. Windows executable discovery recognizes `Path`/`PATH`, native path-list separators and `PATHEXT`, while retaining Env's explicit-PATH-only policy: it never adds an implicit current-directory search. Raw Unix lookup and compatibility behavior remain unchanged. These limits are resource controls, not an operating-system sandbox. Runtime connection and provider environment bindings are removed from component terminal child environments.

Historical source and portable distribution integrity checks remain available through `DistributionAudit`, separate from native availability. Existing pins, manifest digests and integrity assertions remain intact. `components:setup`, `components:verify` and `components:run` default to the native terminal build; explicit `audit-legacy` and `setup-legacy` retain historical distribution tooling. First-run setup prepares Pi and runtime settings without installing a component toolchain.

## Validation and limits

The wiring plan requires workspace fmt, Clippy, tests, hygiene/frontend checks, all Atlas reference comparisons and Beacon terminal comparisons, plus bounded hostile-input and child-cleanup checks. Actual results belong in the plan evidence. Native Windows checks cover production lint, selected process/runtime/CLI/store fixtures and executable aliases; this is not exhaustive Windows behavior or packaging evidence. Native macOS execution, release archives, installed distribution aliases and consolidated CI remain separate obligations. Compatibility version metadata may still describe the historical tool; backend availability is reported independently.

Developer component commands reuse the binary built by explicit `components:setup`/`components:verify`. They respect `CARGO_TARGET_DIR` and refuse a missing binary rather than starting a build inside an arbitrary command environment. The smoke harness carries that nonsecret build-target setting into its isolated nested launcher. No credential, installed tool or global configuration is migrated by these helpers.
