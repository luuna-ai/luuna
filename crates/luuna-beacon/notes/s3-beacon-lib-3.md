## Differences from the Go tool

Every other behaviour copies Go, defects included (A4 differences). The runtime never calls these commands, so no runtime-driven difference is added.

- **RD50-source-path.** Go: import/update open the source path as given, relative to the process cwd, which in Go is the project root (cli.go:1071, :1101; artifact.go:23). Library: artifact_import/artifact_update take the source as a &Path; a relative path is joined to the project root for filesystem access, and messages show the path exactly as given. Why: The library never reads the process cwd (foundation AS1). Same result for the same argv when the wiring's cwd is the project root.
- **RD51-bounded-read.** Go: encode reads the whole file (artifact.go:76) and then refuses it if it is larger than 4 MiB (:80-82). Library: reads at most 4 MiB + 1 bytes and refuses with the same message `artifact file exceeds 4 MiB: <logical>`; check order (read error, size, credential name, encoding) is Go's. Why: Same output for every file that does not change during the read; memory stays bounded (PIPELINE rule 10). Go's unbounded read is GD81.
- **RD52-git-runner.** Go: sync runs exec.Command("git", ...) with the parent's whole environment (cli.go:1708-1712). Library: SyncOptions.git: GitRunner { program, environment }. Default: program `git`, GitEnvironment::Inherit (the child gets the parent's environment, as Go). GitEnvironment::Exact(list) clears the child's environment and sets exactly the list. Why: The library must not read the environment, and tests must isolate git on the library side too (A4 tests_with_git). Default equals Go.
- **RD53-ids-and-suffixes.** Go: artifact id `artifact-` + %x of UnixNano (artifact.go:137); export stage/backup suffixes %x of UnixNano (cli.go:1248, :1277, :1279). Library: both from Beacon::next_id_hex(), strictly increasing per project root within one process (foundation AS16). Why: Differs only where two values would fall in the same nanosecond or a fixed clock is used.
- **RD54-sync-date-clock.** Go: commit message date from time.Now().UTC() (cli.go:1736). Library: from the handle's clock (now_text), the system clock unless Beacon::with_clock is used. Why: Same text with the default clock; lets a Go-free test fix the date.
- **RD55-onboard-unreadable-target.** Go: onboard discards the read error of the target (cli.go:1353) and then writes the snippet as the whole file (cli.go:1383-1390), so an existing file it cannot read is replaced by the snippet (GD64). Library: In Apply mode, if reading the chosen target fails with any error other than not-found, onboard returns ArtifactsError::OnboardUnreadable and writes nothing. Check and Stdout keep Go's behaviour (they write nothing). A target that is a directory is refused the same way (Go fails there too, at the write, with an OS error). Why: A8 data loss (charter.json:218); slots plan.md:99 and :142. Error: `refusing to overwrite <target>: it cannot be read: <os error>`.
- **RD56-non-utf8-source-path.** Go: the stored path is the walk's relative path (artifact.go:42-43) or the base name of a single-file source (:32); json.Marshal writes it into artifacts.jsonl (store.go:95) and into the manifest (artifact.go:153), and encoding/json replaces each invalid UTF-8 byte with U+FFFD, so a path that is not valid UTF-8 is stored, verified and exported under a different name, and two such names can collapse into one. Library: After Go's own checks for that file (read, size, credential name), a logical path that is not valid UTF-8 is refused with ArtifactsError::NonUtf8Path; nothing is appended and artifacts.jsonl is untouched. Why: A8 decided item 6: a written value that reads back as a different value is refused unless Go is shown to read it back the same. Go's documented encoding/json rule is that it does not; the parity test records what Go stores. Error: `refusing to store a path that is not valid UTF-8: <path with U+FFFD>`.
- **RD57-export-escape-onto-existing-file.** Go: exportArtifact joins each stored path to the stage with no containment check (cli.go:1289) and writes it with a truncating os.WriteFile (:1293), so a stored path with `../` (artifacts.jsonl is merge=union and can arrive by a merged branch) overwrites any existing file it reaches (GD51). Library: Before the stage is created (after Go's destination, --force and marker checks), every stored path is joined to the stage name and cleaned lexically; if the result is outside the stage and anything exists at that name (symlink_metadata succeeds), export returns ArtifactsError::ExportWouldOverwrite and writes nothing. An escaping path to a name where nothing exists is still written, as Go (GD51 copied). Why: A8 data loss: a user's file rewritten without the content it held. Narrow on purpose so every other GD51 behaviour stays copied. Also refused, where Go would instead fail with an OS error or follow a dangling link: an existing directory or a dangling symlink at the escaped name (recorded difference, no data involved). Error: `refusing to overwrite <path> outside the export directory`.

### Decided under A8

1. `--force` export replacement (DL4, DL5): copied. The user asked for replacement explicitly; without `--force` Go refuses (`cli.go:1235`, `:1269`), and directory replacement needs Beacon's marker.
2. Onboard managed block (DL6): copied. The markers declare the block as Beacon's; a user's own text placed between them is replaced on update, as Go does. Text outside the block is kept byte for byte.
3. Onboard plain write (DL7): copied. The error is reported. An atomic replace would change which file a symlinked target writes (GD68), and its mode.
4. `doctor --fix` (DL8), snapshot exclusions and modes (DL9), read-only key drops (DL10): copied. No user file loses content.
5. Refusal boundaries (AS62). RD55 applies only in Apply mode, on a read error other than not-found. RD56 applies after Go's own checks for that file. RD57 applies only when something exists at the escaped name; it also refuses an existing directory or a dangling link there, where Go would fail or follow the link (recorded differences that involve no data).
6. RD56 without an observed Go run. Decision 6 refuses unless Go is shown to read the value back the same, so a refusal needs no prior observation; the parity test records what Go stores.

## Process use (AS52)

`src/artifacts/sync.rs` is the only source file that starts a process; the library reads no environment variable, uses no shell, and receives git's program and environment only through `GitRunner` (RD52). Every place a program is started, library and tests:

- **crates/luuna-beacon/src/artifacts/sync.rs (Beacon::sync), the only src file that may start a process (AS52).** Go: internal/cli/cli.go:1708-1712: exec.Command("git", arguments...) (exec.LookPath over the Go process's PATH), command.Dir = ctx.cwd, environment inherited (Env nil), CombinedOutput. Program: GitRunner.program, default the bare name `git`. With GitEnvironment::Inherit it is looked up on the parent process's PATH, as Go. With GitEnvironment::Exact(list) containing PATH, Rust std on Unix searches that PATH (risk: proven by artifacts_api and the missing-git case). No shell is ever used. Arguments: `status --porcelain .luuna/beacon/`; `add .luuna/beacon/`; `commit -m luuna-beacon: sync <YYYY-MM-DD>` Working directory: Beacon::project_root() Environment: Inherit: the child gets the parent's environment unchanged; the library reads no variable. Exact(list): env_clear, then exactly the list. Stdio: stdin null; stdout and stderr both on the write end of one std::io::pipe, read to end, then wait: Go's CombinedOutput. Failure to start: ArtifactsError::Git { step, output: "" }, Display `git status: ` (Go's text).
- **tests/support/artifacts.rs Pair Go runner (new).** Program: the absolute path go::go_build().binary (frozen go.rs:210-227). Arguments: the step's Go argv followed by `--json`. ## Assumptions

- **AS50-artifact-ids-through-the-project-pattern.** Artifact cases run in Case::with_project("artifact"); Pair sides use Normaliser::new("artifact", root); cases that also store prompts write `project: artifact` to config.yaml on both sides. Why: normalise.rs:134-140 numbers `<project>-<hex>` ids; artifact ids are `artifact-<hex>`. No harness edit needed.
- **AS51-argument-order-in-the-library.** Artifact methods take Go's positional arguments as Option or empty-string inputs and report Go's argument errors after the store prologue; artifact_store_check is public. Why: Go checks the store before arguments (cli.go:1020-1038 before :1064); keeps the wiring a thin argv layer.
- **AS52-git-in-one-file.** std::process is used only in src/artifacts/sync.rs, with GitRunner (RD52). Why: Reserved there by the slots plan (plan.md:76; review-security.json:27); one file keeps the ban checkable.
- **AS53-own-pair-runner.** tests/support/artifacts.rs has a Pair runner (two fresh_root sides, optional outside folders and test-made git repositories, the Go binary started by absolute path with the test_isolation environment) for sync, onboard --stdout, cases whose documents name an outside folder, prime with a refused migration, onboard with a legacy layout, the A8 refusal cases (Go and library differ by design), and doctor cases with parser texts. Why: run_go's empty PATH and git-root refusal are frozen (go.rs:358-412). Pair keeps the same comparisons (exit code, documents after normalisation, exact errors with the OS-prefix exemption via assert_errors_match, the migrated line, store snapshot via the public snapshot()).
- **AS54-plan-steps.** Every other case runs through Case::step with Step::Plan(Box<ArtifactStep>) and Done::Plan(Box<ArtifactDone>); files outside the compared store (exports, CLAUDE.md, AGENTS.md) are compared after each step by compare_outside (type, bytes, mode, symlink target text with <root>, no `.lbc-stage-`/`.lbc-backup-` left). ArtifactStep never overrides PlanStep::written_paths: its raw steps write only outside .luuna/beacon (source trees, symlinks, outside files), and any store file a case writes by hand (artifacts.jsonl lines, `.lock` files) goes through the foundation's Step::WriteFile/SetMtime. Why: Uses the slot the slots plan built; satisfies security finding 2 (review-security.json:14-18) by not using the exemption at all.
- **AS55-doctor-parser-texts-revised.** sort_map_ordered only sorts. Doctor cases whose failing details carry parser or OS texts (config, prompts-integrity, schemas-integrity, artifacts-integrity parse failures) run through Pair, whose document comparison, for those detail strings only, compares the recognised prefix (`invalid JSONL line <n> in <path>: `, `<op> <path>: `, `yaml: `) and every other field exactly. Artifact Verify texts are compared whole. Why: The foundation compares the same parser and OS texts by prefix only (case.rs:11-13); Rust cannot reproduce encoding/json and yaml.v3 messages. Doing it in Pair keeps the hook a pure reorder (security finding 3).
- **AS56-hostile-tests-separate.** Hostile tests are #[ignore]d in their own file and run only under the wrapped command. Why: cargo test --workspace runs non-ignored tests without a memory limit.
- **AS57-stale-lock-clock.** doctor's 30-second staleness uses SystemTime::now(), not the handle's clock. Why: Go uses time.Since (cli.go:1464); the foundation's store.rs does the same.
- **AS58-bytes-not-strings.** onboard and prime work on file bytes; marker search and splicing are byte operations. Why: Go's string() of file bytes keeps invalid UTF-8.
- **AS59-iterative-walk.** The snapshot walk uses an explicit stack in WalkDir's lexical order. Why: Deep nesting must not exhaust the stack; order matters for the 256 cap.
- **AS60-no-to-payload.** The library builds no JSON envelopes for these commands. Why: Foundation AS5; the runtime uses none of these commands.
- **AS61-prefixes-in-mod-doc.** Keep the contract's names (renaming Exported to ArtifactExported) and correct the mod.rs doc line to name the prefixes actually used: Artifact, Doctor, Prime, Onboard (and ONBOARD_), Git and Sync. Why: Slots reviewer finding 2 (review-reviewer.json:17-22) leaves the choice to this plan, which owns mod.rs. Names like ArtifactDoctorCheck or ArtifactGitRunner would not describe the items; distinct prefixes keep the glob re-exports free of clashes with -2 (checked by name).
- **AS62-a8-refusal-boundaries.** RD55 refuses only in Apply mode and only on a read error other than not-found; RD56 checks after Go's own checks for that file; RD57 refuses only when something exists at an escaping name, before the stage is created. Why: Each refusal is as narrow as the loss, so every other Go behaviour (including GD51, GD64's check mode, GD68) stays copied (A4 differences).
